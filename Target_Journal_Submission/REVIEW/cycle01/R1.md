# R1 — Statistical theory review (cycle 01)

Lens: Proposition 1 and its proof, rank formulas, dead-cell handling, truncation, PAC variant, Table S12 (T13),
and the inferential statistics (Monte-Carlo CIs, Wilcoxon/Holm, bootstrap). Theory was cross-checked against
`code/src/batscreen/screening/calibration.py`, `procedure.py`, `evaluation/runner.py`,
`statistics/tests.py`, `experiments/analysis.py`, `experiments/suite.py` and the raw E1/E10 results.

## What I verified and found correct

* **Proposition 1 holds.** For the pass side the argument goes path by path: passing at checkpoint m needs
  alive-at-k_m and S^(m) > λ̂, so P_new ≥ S^(m) > λ̂. The event "passed at some checkpoint" is contained in
  {P_new > P_(r0)} under any stopping time, any check order and any operator abort. The step
  P(P_new > P_(r0)) ≤ (n0+1−r0)/(n0+1) ≤ α holds with ties because the inequality is strict. The good-cell side
  is the same argument (good cells are alive at every k_m < L*, so R_i = max over all m is correct).
* **Dead cells.** In calibration, `alive = isfinite(S)`. In `runner.predict_models`, S is NaN exactly where
  T ≤ k_m or no model was fitted at m. `simulate` rejects a test cell when T ≤ k and skips non-finite S, so
  "alive" means the same thing for calibration and test cells. P_i is a fixed function of a cell's own
  trajectory, so masking dead checkpoints with −∞ keeps exchangeability. A bad cell that dies before k_1 gets
  P_i = −∞, which `conformal_upper` keeps. In E1 no test cell lacked a score (checked: 0 cells).
* **Ranks.** `math.ceil((n+1)*(1-alpha))` gave the same result as an exactly rounded ceiling for every n ≤ 500
  and α ∈ {0.01, 0.05, 0.1, 0.15, 0.2}, so there is no floating-point off-by-one. These statements check out:
  passing needs n0 ≥ (1−α)/α = 9 at α = 0.1 and 19 at α = 0.05; Bonferroni gives +∞ iff n0 < M/α − 1 = 159
  (M = 16); "⌈1/α⌉ − 1 = 9" (Section 4.5).
* **Truncation at min(T, L*).** This is correct for the thresholds, because P_i, R_i and Z_i use only checkpoints
  k_m < L* and the label. Training uses `tr` only and calibration uses `ca` only, so I found no leakage.
* **PAC rank.** `pac_rank(n, 1−α, δ)` returns the smallest r with Beta(r, n+1−r).cdf(1−α) ≤ δ, which is the
  correct condition for coverage of a continuous i.i.d. order statistic. Minimum n: 22 at α = δ = 0.1
  (0.9^22 = 0.098 < 0.1 < 0.9^21 = 0.109), 16 at δ = 0.2 and 45 at α = 0.05, δ = 0.1. The E10 raw data agree:
  `traj_pac` had λ̂ = +∞ in exactly the splits with n0 < 22 (MATR default 75%, HUST large_cal 80.5%,
  HUST default 100%).
* **Table S12 (`tables/T13_conditional_error_analytic.csv`).** I recomputed all nine rows (marginal rank,
  P(conditional error > α) = Beta(r, n+1−r).cdf(0.9), and the PAC ranks at δ = 0.1 and 0.2). All match. For
  example, n = 20 gives r = 19, P = 0.392, PAC rank (δ = 0.2) = 20, and no rank at δ = 0.1.
* **Monte-Carlo CIs for validity.** Given the dataset and the training set, calibration and test cells are a
  uniform random partition of a fixed pool (`stratified_split`), so the class-conditional guarantee holds
  *exactly for this finite pool*. Splits are i.i.d. given the data, so a normal-approximation CI over split
  means is a valid Monte-Carlo CI for the conditional expectation. This is the right tool for checking the
  theorem (see R1-09 on wording).

## Findings

### R1-01 — MAJOR — The PAC variant is used in Results and Discussion but never defined in Methods
* **Location:** Draft_Manuscript.md:200 ("The training-conditional (PAC) variant with δ=0.10 (Section 3.3)"),
  :235, :237, :243; Section 3.3 (lines 68–92) contains no PAC definition.
* **Evidence:** `grep PAC` finds no definition in Methods. The rule exists only in code:
  `calibration.py` `pac_rank`, plus `method == "traj_pac"` with `delta` hard-coded to 0.1. Its assumptions are
  stronger than those of Proposition 1 and are not stated. The Beta(r, n+1−r) coverage law needs **i.i.d.
  draws with continuous scores** from an infinite population. Exchangeability alone does not give a
  training-conditional guarantee, and E10 draws calibration and test cells without replacement from a finite
  pool of about 85 or 46 cells.
* **Fix:** Add to Section 3.3 a "Remark (iv)/Proposition 2". Define r_δ = min{r : Beta(r, n+1−r).cdf(1−α) ≤ δ}
  and λ̂_δ = P_(r_δ). State the guarantee P_cal{P(pass | cal, Z=0) > α} ≤ δ under i.i.d. sampling. Note that
  ties and −∞ atoms make the rule conservative. Give the minimum n, ⌈log δ / log(1−α)⌉ = 22. Make δ a
  parameter in code instead of a literal.

### R1-02 — MAJOR — The paper gives the wrong reason why realised error rates fall below 0.10; the bound is nearly tight
* **Location:** Draft_Manuscript.md:152: "The rates are below the nominal 0.10 because the maximum statistic
  is conservative when the scores of later checkpoints add little beyond earlier ones."
* **Evidence:** I recomputed from `results/raw/E1_*_splits.csv` and `E1_*_scores.csv.gz`:

  | | attained level E[(n0+1−r0)/(n0+1)] | P(P_new > λ̂), bad test cells | realised FPR | attained level, good | P(min S < −μ̂), good | realised FRR |
  |---|---|---|---|---|---|---|
  | MATR/CLO | 0.081 | 0.084 | 0.068 | 0.084 | 0.086 | 0.080 |
  | HUST | 0.076 | 0.072 | 0.068 | 0.078 | 0.077 | 0.074 |

  The gap is not caused by the maximum statistic:
  * Most of the distance from 0.10 comes from rank discreteness. With n0 ≈ 20, r0 = 19 gives 2/21 = 0.095. With
    n0 ≈ 12 on HUST, the attained level is 1/13 = 0.077.
  * The probability that the maximum statistic crosses λ̂ matches the attained level within Monte-Carlo error.
    So for a pass-only rule the maximum is essentially exact.
  * The remaining FPR gap (0.084 → 0.068) comes from bad cells that are rejected by the model, or fail, before
    their trajectory would have crossed λ̂.
  * On the reject side the bound is almost attained (0.080 vs 0.084).
  * The stated mechanism ("later checkpoints add little") would make the maximum close to the first score and
    the bound *tighter*, not looser.
* **Fix:**
  * Replace the sentence with the decomposition above.
  * Report the attained level next to the nominal 0.10 in Table 2, and judge validity against it.
  * Optionally mention two ways to recover efficiency:
    * randomised (smoothed) conformal ranks, which attain α exactly;
    * rule-specific calibration (R1-10).

### R1-03 — MAJOR — Cell-level Wilcoxon/Holm/bootstrap inference treats dependent cells as independent, and the two tests disagree in ways the text does not address
* **Location:** Section 3.6 (line 113); Table 3 (lines 162–179); `statistics/tests.py:58–98`.
* **Evidence:**
  1. Each cell's averaged time to decision depends on the *other* cells, because they form its training and
     calibration sets. Per-cell differences are therefore not independent.
  2. MATR cells form clusters: 78 protocol groups, with sizes 1×43, 2×17, 3×3, 4, 5×10, 6, 7, 8×2.
  3. The cell bootstrap resamples fixed per-cell averages. It never refits or recalibrates, so it cannot
     reflect the variability of thresholds under a different cell population.
  4. p-values such as 1.2e-28 are the minimum attainable p for n = 169 under a normal approximation (identical
     for Bonferroni and naive). They signal "every cell has the same sign", not population-level evidence.
  5. The rank-based test and the mean-based CI contradict each other twice. For MATR Parametric, the saving
     difference is +0.8 pp (CI −1.4 to 3.2) in favour of the proposed rule, yet Holm p = 0.0015 with r = +0.31
     in favour of the *comparator*. For MATR Point@100 it is the reverse: CI −9.3 to −3.5 excludes 0, but
     p = 0.16. The two procedures target different estimands (pseudo-median of per-cell cycle differences vs
     ratio-of-sums time saved). The text only discusses the single-checkpoint comparison.
* **Fix:**
  * Report one estimand (the saving difference) with its Monte-Carlo CI conditional on the dataset (split-level
    paired differences).
  * If population-level inference is wanted, use a protocol-cluster bootstrap that refits and recalibrates
    (or a few hundred outer resamples of cells).
  * Drop the Wilcoxon p-values or label them clearly as descriptive.
  * Explain the sign conflicts in Table 3.

### R1-04 — MINOR — Proposition 1 is stated informally; several conditions are implicit
* **Location:** Draft_Manuscript.md:86–90.
* **Evidence:**
  * "Exchangeable within class" needs a precise meaning. One option: (X_i, T_i) i.i.d., so that conditional on
    all labels the bad trajectories are exchangeable. Another: exchangeable conditional on (n0, n1).
  * The proof silently conditions on n0.
  * The rank argument assumes a random tie-break, but the procedure is deterministic. The strict ">" is what
    makes the deterministic version conservative; the proof should say so.
  * Implicit conditions: the grid {k_m}, the predictors h_m, the scales s_m and α are fixed before calibration
    data are seen; looks at cycles outside the grid are not covered; updating λ̂ as more calibration cells
    accrue during a campaign is not covered.
  * For the GP, s is a per-cell posterior SD. That is fine because it is a function of the cell's own features,
    but it should be said.
* **Fix:** Add a formal assumption ("A1: conditional on Z_1..Z_n, Z_new = 0, the vectors (S_i^(·), T_i ∧ L*)
  of bad cells are exchangeable; h_m, s_m and the grid are measurable with respect to the training data only").
  Replace "ties broken at random" with the strict-inequality argument, and list what is not covered.

### R1-05 — MINOR — The protocol-disjoint experiment (E9) is outside Proposition 1, but the text implies it is covered
* **Location:** Draft_Manuscript.md:206 ("the rule remained valid … since calibration and test cells still
  came from the same protocol population"); `experiments/suite.py:282–306`.
* **Evidence:** E9 assigns whole protocol groups (sizes up to 8) to calibration or test. A test cell is then not
  exchangeable with individual calibration cells, because its group-mates are all in test. Only group-level
  exchangeability holds, and the cell-level rank argument does not apply.
* **Fix:** Present E9 as an empirical robustness check. Either state that cell-level exchangeability is
  violated and the observed validity is empirical, or note that a group-level guarantee would need group-level
  scores.

### R1-06 — MINOR — The comparison of "share of splits above 0.10" with Table S12 and with δ mixes different quantities
* **Location:** Draft_Manuscript.md:200 ("consistent with the analytic probability … 39%"); :235;
  Table S11 columns "fpr split above alpha".
* **Evidence:**
  * Table S12 gives P(*conditional* error of the P-threshold > α) for i.i.d. continuous scores.
  * The empirical share is P(*realised* FPR on about 20 or 12 bad test cells > 0.10). That share includes
    binomial test-set noise: with a true conditional error of 0.05 and 20 test cells, P(≥3 false passes) ≈ 0.075.
  * It also excludes the rejection effect of R1-02, so 39% is an upper bound for the actual rule.
  * The 4%/8% PAC shares therefore do not test δ = 0.1, and "consistent with 39%" (observed 28%) is not a
    meaningful check.
  * n0 varies across splits (MATR 12–28), and the Beta probability jumps with n (n = 20: 0.39; n = 22: 0.34;
    n = 25: 0.27).
* **Fix:** Estimate the conditional error per split from all bad cells outside the calibration set, or average
  the Table S12 probability over the empirical n0 distribution. Label the realised-FPR share as such.

### R1-07 — MINOR — Overclaims about PAC and the workflow threshold
* **Location:** Draft_Manuscript.md:235 ("a training-conditional (PAC) variant removes this"); :237
  ("preferably more than 22 of each"); :243 ("unless the PAC variant is used").
* **Evidence:** PAC bounds the probability of excess conditional error by δ; it does not remove it. The
  requirement is n ≥ 22, not > 22.
* **Fix:** Use "bounds this probability by δ" and "at least 22 (α = δ = 0.1)".

### R1-08 — MINOR — The exceedance shares for the same design are reported inconsistently
* **Location:** Draft_Manuscript.md:152 (26% / 21%, E1, 1,000 splits) vs :200 (28% / 24%, E10 default, 200 splits).
* **Fix:** Quote one source, or name the experiment each time.

### R1-09 — MINOR — The scope of the CIs and the "valid" flag in Table S9 are misstated or anti-conservative
* **Location:** `experiments/analysis.py:166–167`; Table S9 (`tables/T10_sensitivity.csv`); Section 3.6.
* **Evidence:**
  * `fpr_le_alpha = mean <= alpha + 1.96*SE` marks a rule "True" whenever its mean is not significantly
    *above* α. This puts the burden of proof on the wrong side: naive at α = 0.2 has FPR 0.206 and is flagged
    True.
  * The Methods do not say that the CIs are conditional on the 169/77 cells. They answer whether the finite-pool
    guarantee is met, not what the error rate would be for a new population.
* **Fix:** Report the mean with its upper CI and drop the Boolean, or define it as "upper CI ≤ α". Add one
  sentence: "CIs quantify Monte-Carlo error conditional on the data set; because calibration/test assignment is
  a uniform random partition, Proposition 1 applies exactly to this finite pool."

### R1-10 — MINOR — Remark (ii) overstates exactness; a sharper valid calibration exists
* **Location:** Draft_Manuscript.md:92 ("The maximum statistic accounts for the dependence between looks exactly").
* **Evidence:** The statement is exact only for the pass-only first-crossing event. With concurrent rejection,
  FPR is 0.068 against a crossing probability of 0.084 (R1-02). μ̂ depends only on good calibration cells, so
  a bad calibration cell's statistic can be computed over checkpoints *before it would have been rejected* by
  −μ̂ (and symmetrically for good cells). This keeps exchangeability, stays valid for the specific rule, and
  gives a lower λ̂. The cost is the "any order of checks" robustness. Size of the efficiency gain: UNVERIFIED,
  because calibration-cell scores are not stored.
* **Fix:** Say "exactly for the pass-only rule; conservative when rejection is applied concurrently", and
  mention the rule-specific variant as a trade-off.

### R1-11 — MINOR — The validity unit test does not exercise dead cells, the reject side or PAC
* **Location:** `code/tests/test_calibration.py:9–43`.
* **Evidence:** `_synthetic` gives every cell finite scores at every checkpoint, including checkpoints after
  death (T can be about 124 < 130). So the `alive` masking, `P_i = −∞` and NaN handling are never tested, and
  calibration scores after death are used, which the paper's Equation (3) forbids. Only FPR is asserted.
  There is no test of FRR, `traj_pac`, `single` (including dead cells as −∞), or adversarial stopping orders.
* **Fix:** Set S to NaN where T ≤ k_m. Assert both FPR and FRR ≤ attained level + MC error. Add a pac_rank
  test (n = 21 → None, n = 22 → 22). Add a test in which the reject check runs before the pass check, and one
  with random operator aborts.

### R1-12 — MINOR — "Truncated test campaigns" applies only to calibration in the headline results
* **Location:** Title; abstract; Remark (i).
* **Evidence:** The main elastic net regresses log10 T. `runner._evaluate` sets `train_cell_cycles = T[tr]` for
  regressors, so training cells must reach end of life (up to 2,237 / 2,689 cycles). Only the logistic-classifier
  variant truncates training, and it saves 67.5% instead of 78.3% on MATR/CLO and 40.0% instead of 50.7% on HUST.
* **Fix:** Say "truncated calibration campaigns" in the abstract and title, or make clear that full truncation
  needs the classifier base model.

### R1-13 — NIT — The interval rule's inequality differs between text and code
* **Location:** Draft_Manuscript.md:96 ("pass if the lower bound is at least log10 L*") vs
  `runner.py`/`procedure.simulate` (strict `s > pass_thr`).
* **Fix:** Say "exceeds".

### R1-14 — NIT — `conformal_upper` silently drops +∞ and NaN values, and `pac_upper` does not
* **Location:** `calibration.py:27`.
* **Evidence:** `v = v[isfinite(v) | (v == -inf)]` would reduce n, which is anti-conservative, if any
  calibration statistic were +∞ (for example a zero scale). The path is currently unreachable because
  `_traj_max` and the per-checkpoint branches mask non-finite S. `pac_upper` has no filter at all, so the two
  helpers behave differently.
* **Fix:** Raise on +∞ or NaN instead of dropping, and apply the same handling in `pac_upper`.

## Overall recommendation

**Minor revision on the statistical theory.** Proposition 1 and its proof are correct. Dead cells, rank
formulas, truncation, the PAC rank and Table S12 all match the code and my recomputation. What needs work is how
the guarantee is explained and what inference is drawn around it: the PAC variant is undocumented, the reason
for the conservativeness is wrong, and the efficiency tests treat cells as independent.

### The 3 changes that matter most
1. **R1-01:** Define the PAC variant formally in Methods (rank, δ, i.i.d./continuity assumption, n ≥ 22).
2. **R1-02:** Replace the "maximum is conservative" explanation with the decomposition: rank discreteness
   (attained level 0.081 / 0.076) plus competing rejection. Report the attained level in Table 2.
3. **R1-03:** Replace or relabel the cell-level Wilcoxon/Holm/bootstrap analysis. Use split-level Monte-Carlo
   CIs conditional on the data, or a protocol-cluster bootstrap that refits and recalibrates, and resolve the
   sign conflicts in Table 3.
