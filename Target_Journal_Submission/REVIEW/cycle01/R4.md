Lens: line-by-line audit of `code/src/batscreen` and `code/experiments`, compared with Methods 3.2–3.6. I also ran the test suite and some independent checks.
Scratch scripts (not part of the package): `/tmp/claude-0/-home-user-p-c1-3/0430eaaa-3bde-56d0-96f2-4e2463d35486/scratchpad/{syn.py,repro.py,chk.py}`.

## What I verified and found correct

These are listed so that later cycles do not re-audit them.

* **Test suite.** `cd code && python -m pytest -q` gives `4 passed in 2.53s`.
* **Bit-exact reproduction.** I re-ran `run_split` for E1 seeds 20261115 and 20261122 on both data sets, in a fresh process outside joblib. The stored rows in `results/raw/E1_*_splits.csv` match to ≤4.4e-16 (fpr, frr, time_saving, early_rate, pass_thr, rej_thr, n_cal_bad). The parallel runs are therefore deterministic and order-preserving: joblib returns results in input order, and each split carries its own seed.
* **Rank and quantile.** `conformal_upper` (calibration.py:25-35) returns `v[r-1]` with `r = ceil((n+1)*level)` and +inf when r>n. This matches Eq. (4) and is 1-based correctly. Float `ceil` agrees with the exact rational value for all n<500 at levels 0.80, 0.90 and 0.95. `pac_rank(n, 0.9, 0.1)` first exists at n=22, which matches the "22 cells" claim in 4.5. Beta(19,2) at 0.9 gives 0.392, which matches "39%".
* **Inequality directions.** Pass uses `S > pass_thr` (strict) against the order statistic of the bad-class maxima. Reject uses `S < -mu` with `mu` the quantile of `max(-S)` over good cells. Both are consistent with the proof of Proposition 1, ties included, because P(V_new > V_(r)) ≤ (n+1-r)/(n+1) holds with ties.
* **Death and NaN handling.** Feature rows are NaN exactly when `T <= k` (features.py:333; checked: 0 dead cell-checkpoints with finite features and 0 alive cell-checkpoints with NaN features in either data set). Predictions are made only for `T > k` (runner.py:223). Calibration treats non-finite scores as "not alive" (`_traj_max` sets them to -inf, so a bad cell that is never alive gets P=-inf). `simulate` checks `T <= k` before looking at the score and rejects by observation at time T. These rules agree on a cell with T equal to a checkpoint (one MATR cell has T=300).
* **Exchangeability of the splits.** `stratified_split` stratifies only the training set and then permutes the pool uniformly into cal/test. Given the training set, calibration and test cells are therefore exactly exchangeable within each class, as Section 3.6 states. HUST: 31 training, 23 calibration and 23 test cells, as expected.
* **Metric definitions match Section 3.6.**
  * FPR = false passes / bad test cells.
  * FRR = false rejects / good test cells.
  * early_rate = share of all test cells decided at a checkpoint (`by_model`).
  * time_saving = 1 − Σtime / Σmin(T, L*).
  * No split had zero bad or zero good test cells in E1, so the `max(·,1)` guard never biased FPR or FRR.
* **Independent synthetic validity check** (`syn.py`, 4,000 replicates per setting). Exchangeable scores were generated with the HUST checkpoint grid, cells dying before checkpoints (NaN), and n_cal ∈ {10, 23, 42}, with and without heavy ties. The trajectory rule's pooled FPR/FRR was 0.060/0.056 (n=23), 0.022/0.022 (n=23, ties), 0.061/0.064 (n=42) and 0.001/0.001 (n=10), all ≤ 0.10. Naive sequential calibration gave 0.19–0.21, and Bonferroni gave 0.
* **No stale chunks were mixed in (checked through git history).** After the E1 MATR/CLO results were committed (59d7379), calibration.py and runner.py changed once, in 257ead3, and that change only adds `traj_pac`. All other chunks were produced after the last source change.
* **Exposure and model seeds** are distinct between experiments (offsets 0..800000, n ≤ 1000). The pilot seeds (1000–1099) are disjoint from the main seeds.

No CRITICAL defect was found: the reported error rates come from code that implements the stated rule correctly.

## Findings

### R4-01: MAJOR. The score scale s_m is optimistically biased, which handicaps the parametric comparator
* **Location:** models/base.py:39-42 (`ENModel.fit`); manuscript 3.2 ("s_m is the out-of-fold RMSE…"), 3.4 (parametric threshold), 4.2 and Discussion ("Model-based uncertainty is not a substitute").
* **Evidence:** s_m is `sqrt(mse_path_[li, ai].mean())` at the *selected* (minimum-CV-error) penalty and l1 ratio. This is the minimum over a 4×40 grid, so it is downward biased by selection, and the imputer and scaler are fitted on all training cells before the internal CV. Pooling the E1 test scores (`E1_*_scores.csv.gz`), the actual test RMSE of log10 T divided by the mean s_m was:
  * MATR/CLO: 1.02–1.26 across checkpoints (e.g. 1.26 at k=140, 1.12 at k=100);
  * HUST: 1.04–1.14 (1.14 at k=600).
* **Consequence:** the Gaussian rule `S > z_{1-α}` is anti-conservative by construction. Part of its failure on HUST (FRR 0.136) is an artefact of this scale, not evidence that "model-based uncertainty" fails in general. The proposed rule is unaffected, because rank calibration is invariant to a per-checkpoint scale, but the comparison is not like-for-like.
* **Fix:** either estimate s_m with nested CV or refit at the chosen penalty on held-out folds, or add a sensitivity row in which the Gaussian rule uses a scale estimated on separate cells. At minimum, state the bias in 3.2/3.4 and soften the Discussion claim.

### R4-02: MINOR. E9 (protocol-disjoint) is described as satisfying the guarantee, but cell-level exchangeability does not hold there
* **Location:** suite.py:294-300; manuscript 4.6 ("the rule remained valid … since calibration and test cells still came from the same protocol population").
* **Evidence:**
  * Whole protocol groups go to cal or test by an independent coin flip (`to_cal = rng.random(len(rest)) < 0.5`). Cells of a calibration group and a test group are therefore exchangeable only at the group level, and within-group correlation means Proposition 1 does not formally apply.
  * Group assignment makes set sizes highly variable: n_cal ranges 21–73 and n_test 11–64, with as few as 2 good test cells in a split.
  * FRR upper CI = 0.101.
* **Fix:** describe E9 as an empirical stress test outside the theorem's assumptions, not as "valid … since". Report the n_cal and n_test ranges. Optionally use a group-conformal (one score per group) variant if a guarantee is wanted.

### R4-03: MINOR. Resume and chunk logic has no fingerprint of configuration, code or environment
* **Location:** suite.py:24-38 (`_exists`, `_chunk`); run_all.py:362.
* **Evidence:**
  * A chunk is reused whenever `results/raw/chunks/<name>.csv` exists. The name encodes only dataset and level, not n_splits, alpha/beta, seeds, code version or library versions.
  * `run_config.json` records only the environment of the *last* invocation, but the results were produced across at least three containers (EXPERIMENT_LOG: worker restart at ~17:00 and container restart at 22:2x).
  * I found no actual contamination (see the git history check above), but nothing in the pipeline would detect it.
* **Fix:** write a sidecar JSON per chunk (config subset, seeds, git hash, library versions) and refuse to reuse a chunk on mismatch. State in the SI that results were assembled from resumed runs.

### R4-04: MINOR. The test suite does not exercise the code paths the guarantee depends on
* **Location:** tests/test_calibration.py.
* **Evidence:**
  * `_synthetic` gives every cell a score at every checkpoint, including after death, so `alive` is all True. The death-before-checkpoint path of `_traj_max` and `simulate` is therefore untested.
  * Only FPR is asserted. FRR, `single`, `interval_calibrate`, `traj_pac`, `metrics` and `stratified_split` exchangeability have no tests.
  * Splitting is a fixed first-60/last-60, not the production splitter.
  * The earlier exchangeability bug (EXPERIMENT_LOG 16:42) would not have been caught by any test.
* **Fix:** add tests that (a) set S to NaN after T, (b) assert FRR ≤ β+tol, (c) run the real `run_split` on synthetic features and assert mean FPR/FRR ≤ level over ~200 splits, (d) check that `single` counts dead bad cells as −∞. My `syn.py` can serve as a template.

### R4-05: MINOR. The assumption k_M < L* is not enforced
* **Location:** procedure.py:127-138; calibration.py; runner.py `_evaluate`.
* **Evidence:** Proposition 1, the truncation remark and `simulate` all assume every checkpoint is below L*. If a checkpoint were ≥ L*:
  * a good cell with T ≤ k would be "rejected by observation" and counted as a false reject outside the guarantee;
  * calibration would use cycles beyond L*.

  All current configurations satisfy the assumption: the largest checkpoints are 300 and 1000, against L* ≥ 550 and ≥ 1600. Nothing checks it, though, and the E7 L* grid could easily be extended below 300.
* **Fix:** add `assert max(checkpoints) < Lstar` in `run_split`.

### R4-06: MINOR. Overlapping pass/reject zones are resolved silently in favour of "pass"; the Fig. 5 caption is slightly wrong
* **Location:** procedure.py:130-133; manuscript Fig. 5 caption ("Single-checkpoint grids coincide for the three rules").
* **Evidence:**
  * When λ̂ < −μ̂, a score in between satisfies both rules, and the code passes the cell because the pass check comes first. The guarantee still holds, as the proposition covers any order, but the decision rule is not symmetric and this is not documented.
  * This happens in practice. In E3 `single_300` on MATR/CLO, proposed and naive differ: FPR 0.0865 vs 0.0819 and FRR 0.0443 vs 0.0471 (T6_ablation_grid.csv rows 33-34). Part of the difference comes from `traj` counting the two cells that died before 300 as −∞ while `naive` drops them; the FRR difference requires overlapping zones.
  * In E1 the zones never overlapped (0/1000 splits on each data set).
* **Fix:** document the order in 3.3 (or make the rule abstain when the zones overlap), and correct the caption ("coincide except for MATR/CLO cycle 300").

### R4-07: MINOR. Two different quantities are compared as if they were the same; the same statistic is reported with two values
* **Location:** manuscript 4.2 vs 4.5; build_numbers.py split_stats (`fpr_above`).
* **Evidence:**
  * In 4.5 the share of splits with realised test FPR > 0.10 (28%/24%, from E10) is called "consistent with" P(conditional error > α) = 39% (Table S12). The first is a finite-test-sample frequency, with about 20 bad test cells and therefore binomial noise. The second is a property of the calibration threshold. They are not the same quantity.
  * 4.2 reports the same share as 26%/21% from E1, so the paper gives two values for one statistic.
* **Fix:** compare like with like. For example, simulate the realised-FPR exceedance under the Beta law combined with binomial test-set noise, or state the relation only qualitatively. Use one experiment's value consistently, or explain the difference.

### R4-08: MINOR. Abstention on HUST is not reported, and a code comment is false
* **Location:** config/default.yaml:22 ("77 cells: keeps >= 9 cells per class for calibration"); manuscript 4.2/Table 2.
* **Evidence:** in E1 HUST, n_cal_bad ranges 7–17 and n_cal_good 6–16. The pass threshold is +∞ in 23/1000 splits and the reject threshold −∞ in 58/1000 splits, so in those splits the rule never passes or never rejects.
* **Fix:** correct the comment and report the abstention frequencies in 4.2. The `never_pass` token already exists in build_numbers.

### R4-09: MINOR. The cross-model comparison (Table S3/T4) uses different splits and very unequal numbers of splits
* **Location:** suite.py:63-75 (E2 seeds offset 100000) vs E1 (offset 0); analysis.py:114-121.
* **Evidence:** the EN rows come from E1 (1000 splits, seeds +0..999). The other models come from E2 (logit 1000, GBR/RF/GP 200, CNN 30, seeds +100000..). Model differences are therefore confounded with split-sampling noise, and no paired comparison across models is possible. The CNN HUST FRR of 0.113 rests on 30 splits.
* **Fix:** evaluate all models on a common seed set (at least the first 200 E1 seeds) and report paired differences.

### R4-10: NIT. The baseline cycle count is computed from a different population than the table

### R4-11: NIT. Inconsistent split counts and table reference in 3.6

### R4-12: NIT. The text and the code differ on ≥ vs >
* **Location:** manuscript 3.4 (point rule: "pass if the predicted lifetime is at least L*"; interval rule: "lower bound is at least log L*"); runner.py:326-327; procedure.py:130.
* **Evidence:** the code uses strict `>` for both rules. A score exactly equal to the threshold leads to "continue" or "observe", not "pass". The practical effect is nil.
* **Fix:** align the text with the code.

### R4-14: NIT. The validity labels in figures and tables use a lenient criterion that is not stated
* **Location:** figures.py:105; analysis.py:166-167.
* **Evidence:** a rule is flagged "error > nominal" only if the *lower* 95% limit exceeds α. The E7 table uses `mean ≤ α + 1.96·SE`.

### R4-15: NIT. Minor determinism and portability points
* **Location:** utils.py:327; cnn.py:163; base.py:36.
* **Evidence:**
  * `torch.use_deterministic_algorithms` is set only in the parent process, not in the loky workers.
  * The CNN picks CUDA/MPS automatically, so its results will differ by device.
  * `ElasticNetCV(alphas=40)` needs scikit-learn ≥ 1.7 (the integer form of `alphas`). requirements.txt should pin this.
* **Fix:** set the deterministic flag in the worker, force the CPU device for the reproduction run, and pin the scikit-learn version.

### R4-16: UNVERIFIED. The orientation of the HUST V(q) axis
* **Location:** data/hust.py:124 (`q = cap.max() - cap`, commented "discharged capacity").
* **Evidence:** if the HUST "Capacity (mAh)" column already counts discharged capacity upward, then q is *remaining* capacity measured from the end of discharge. In that case the grid [0.02, 0.85] Ah is anchored at the end of discharge, which moves with capacity fade, and the description in 3.2 ("grid of discharged capacity") would be inaccurate. The raw data are not in the container, so I could not check this.

## Overall recommendation (as a journal reviewer, code lens)

**Minor revision.** The screening core is correct and reproducible:
* calibration, decision simulation, death and NaN handling, and the metric definitions match Methods 3.2–3.6;
* stored results reproduce bit-for-bit;
* an independent synthetic check confirms finite-sample validity.

The issues are in comparators, documentation and the safety net, not in the proposed method.

### The 3 changes that matter most
1. **R4-01.** Fix or disclose the optimistic score scale s_m, and re-check the parametric comparator with an unbiased scale before claiming that model-based uncertainty fails.
2. **R4-04 + R4-05.** Add tests that cover death before a checkpoint, FRR and the real splitter, and assert k_M < L*.
3. **R4-02 + R4-07.** Stop describing E9 as covered by the guarantee, and stop equating the realised-FPR exceedance share with the analytic conditional-error probability. Report one value for that share.
